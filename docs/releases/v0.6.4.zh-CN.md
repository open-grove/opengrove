# OpenGrove v0.6.4

[English](https://github.com/open-grove/opengrove/blob/v0.6.4/docs/releases/v0.6.4.md)

OpenGrove v0.6.4 加入可恢复的 App 正式版本管理，简化 Provider 配置并把 Kernel 账号 Login 与模型服务凭据分开，让 App Room 的归属范围变得明确、PM 成为可选成员，为支持的 ACP Kernel 提供受限 Host Tools，补充新账号地区采集，恢复桌面 MCP App 媒体播放，并把桌面部署与提升拆成独立的可信发布门禁。

## 主要变化

### 1. App 支持可恢复的草稿、发布与精确版本切换

每个可见 App 都可以保留一份可编辑的本机草稿，正式版本则由独立 Release Control 服务管理。用户可以在本机修改、预览和保存草稿，再选择某个精确正式版本；切换不会修改 App workspace、Room 历史或聊天数据。检测到真实未保存修改时，切换会明确中断，让用户先保存、放弃或取消。

Admin 可以通过可恢复、幂等的事务发布 App 及完整 Employee 配置。准备、上传或激活中断后可以安全恢复；Release Control 不可用时，远端目录与发布动作会明确失败，但本机草稿仍能打开和编辑。

### 2. Provider 配置采用精选目录，并与 Login 明确分离

OpenGrove 现在内置一份经过审查的 Models.dev 快照，用于公共 Provider 与模型事实。精确的上游模型 ID 会完整保留，不同名称的 Fast、Free、Pro、HighSpeed 和区域线路仍是独立选项。完整模型目录与体积更小的设置摘要分开缓存。

Provider 主列表只显示已连接、已启用或用户添加的服务；未启用的内置项移入可搜索的“添加 Provider”对话框。OpenGrove 不再从其他 Kernel 导入 Provider 配置。Codex、Claude 与 Kimi 账号 Login 改由原生状态、登录和退出命令独立管理；交互式登录在系统终端中打开，不复制也不持久化登录 token。

### 3. App Room 具有明确范围，PM 成为可选成员

App 归属现在保存为明确的 Room scope，不再根据 Room ID 或生成标题推断。标点差异、Room 改名以及外观类似 App 的普通 Room 都无法再改变授权或归属。

App PM 现在是默认 Employee，而不是强制系统角色。App 可以禁用 PM，用户也可以移除或降级 PM，或在没有 PM 时创建有效 App 群组。已有 tombstone、成员和管理员选择保持权威。旧 App Room scope 与可能冲突的 Employee 身份会自动迁移，同时保持消息、事件、workflow、已删除成员引用和归档历史连贯。

### 4. ACP Kernel 可以使用受限的 OpenGrove Host Tools

Kimi 及其他支持 MCP Server 的 ACP Kernel 现在会在新建与恢复 Session 时获得 OpenGrove Host Tool bridge。每份凭据都绑定到具体 Session、Employee、Room 和允许的工具集合，因此普通 Room 成员可以读取当前 Room，但不能跨 Room 读取或越权委派。

工具执行继续复用既有权限、审批与事件记录链路。本机工具 bridge 无法启动时，Session 创建会严格失败；取消与恢复 Session 也会完成资源清理，并且不会修改用户的全局 Kernel 配置。

### 5. 新账号注册明确记录居住地区

当 WW 判断该邮箱将创建新账号时，注册流程会要求从完整 ISO 国家和地区列表中选择居住国家或地区。已有账号登录保持不变。认证后的个人资料会只读显示已登记的账号地区。

该值用于账号服务可用性策略，不会推断支付国家、KYC 国家或数据存储区域；OpenGrove 也不新增本地账号数据迁移。

### 6. 桌面 App 恢复本机媒体播放，并支持更长命令

MCP App 媒体 URL 现在会通过桌面协议代理转发到已认证的本机 Bridge。Range 请求与部分内容响应 header 会完整保留，从而恢复缓存音视频播放，同时不向 App sandbox 暴露任意 Bridge API，也不会注入用户 Cookie。

已声明的 App 命令最长运行时间从一分钟延长到一小时，让合法的长任务可以完成，同时保留参数、输出大小、工作目录和命令声明边界。

### 7. 桌面发布的部署与启用拆成独立可信阶段

发布 workflow 会构建并门禁同一份不可变的 macOS Apple Silicon、macOS Intel 与 Windows x64 候选。最终化阶段从该候选创建正式 tag 与 GitHub Release；部署阶段随后校验并上传相同字节，再向 WW 登记。提升是单独的受保护动作，因此部署不会自动改变当前更新指针，回滚与撤回也保持显式操作。

源码树同时采用隐私安全的公开基线与 Apache-2.0 治理。界面中的 `Claude Code` 集成名称改为 `Claude Agent`；持久化 Kernel ID、Session、模型和聊天历史都不会改变。

## 兼容性与迁移说明

- 本版本的 `clientReleaseNumber` 为 `10029`。
- 从 OpenGrove 0.6.3 升级不需要手工迁移本地数据。App 版本、Room scope 与 Employee 身份迁移会自动执行；无法安全判定归属的旧 App Room 会保留历史并归档，而不是被错误分配范围。
- 精选内置 Provider 名单现在包含 17 个服务。Qianfan、SiliconFlow、ModelScope、StepFun、TheRouter、Novita、NewAPI 和 N1N 等旧预设不再作为内置项提供；用户创建的自定义 Provider 会继续保留。
- Provider 配置不再从 Kernel 配置中导入。Kernel 账号 Login 路由只在运行时投影，绝不会保存成自定义 Provider。
- Release Control 只导入 Store 当前正式基线。已安装的旧 App 版本仍可在本机运行，但切换前的历史版本不会新增远端下载能力。
- npm 包发布与全局安装下的 `opengrove update` / `opengrove upgrade` 路径已停用。源码构建和桌面发布仍正常使用 npm。
- Windows 安装包在 Authenticode 证书到位前仍未签名，首次下载或启动时 Microsoft Defender SmartScreen 仍可能警告。
