# OpenGrove v0.6.6

[English](https://github.com/open-grove/opengrove/blob/v0.6.6/docs/releases/v0.6.6.md)

OpenGrove v0.6.6 将可替换的 Store App 程序与用户持有的 Workspace 分离，并为公开仓建立经过审查的贡献流程与首次发布路径。

## 主要变化

### 1. Store App 程序迁移经过复制校验并且可以恢复

可替换的 Store App 程序会独立于持久用户 Workspace 进行迁移。迁移会在启用前校验复制出的程序代际，保留旧数据用于恢复，回滚未完成的变更，并且绝不阻塞 OpenGrove 启动。诊断导出会记录布局与迁移状态，但不会包含 Workspace 内容。

### 2. 公开 PR 与桌面最终化具有明确的信任边界

公开 PR 必须由 CODEOWNERS 中列出的仓库管理员审批。桌面最终化现在使用受保护的 `desktop-release` environment；同时仍允许一名发版人员自行审批并完成 workflow，不要求第二位操作人参与。

### 3. 首次公开发布仍保留正常的 N-1 更新门禁

由于新公开仓没有更早的 GitHub Release，`v0.6.6` 候选可以使用一次经过固定校验和审查的引导路径，从现有 `v0.6.5` 正式安装包验证升级。其他版本以及首个公开 GitHub Release 创建之后都会拒绝这条路径；后续版本恢复使用正常的上一个 GitHub Release。

### 4. Kernel Run 保留原生生命周期与工具语义

Codex、Claude Agent、Pi、ACP、Hermes 与 OpenClaw 保留各自原生的工具、取消、交互和终态语义。OpenGrove 不再给整个 Turn 统一施加固定墙钟截止时间。Kernel 明确声明的交互截止时间会被遵守；Host 关机和生产者丢失仍是明确的存活边界，并且不会被伪装成用户拒绝或主动取消。

Run 状态现在只有一个权威来源：使用 A2A TaskState 词汇的 `RunRecord.lifecycle.taskState`。`error` 事件只记录诊断，不猜测终态；只有 `turn.finished.outcome` 才能把 Run 结算为完成、取消、拒绝或失败。这样既不会让可恢复的 Provider 错误毒化同一个 Run 的重试，也能把用户取消与失败区分开。

## 兼容性与迁移说明

- 本版本的 `clientReleaseNumber` 为 `10031`。
- 无需手工迁移 Workspace。Store App 布局迁移不会阻塞启动，并会保留旧来源，直到允许执行经过验证的清理。
- 首次公开发布选项只影响发版基础设施，不会改变已安装客户端行为或产品认证。
- 旧版本只写入 `status` 的本地 Run 会在读取时迁移为 `lifecycle`。新快照和 API 不再发布旧的 `RunRecord.status` 镜像；读取 `run.status` 的 App 或外部客户端必须改读 `run.lifecycle.taskState`，使用 `/runs?status=` 的调用方必须改用 `/runs?taskState=`。OpenGrove Desktop 的 UI 与 Bridge 会一起升级，因此这里兼容的是旧磁盘数据，不承诺长期支持新旧客户端混连。
- 审批被拒不再自动意味着 Kernel Run 失败；如果原生 Kernel 可以继续，Run 会继续。反过来，缺少明确 outcome 的 `turn.finished` 会以 `terminal_outcome_missing` 严格失败。
- 待处理交互 API 的审批与提问状态现在都可能返回 `canceled`。客户端必须把它与 `rejected` / `declined` 分开处理；`response.system` 与 `response.reasonCode` 用于区分 Host 对账取消和用户主动取消。
- 用户主动取消审批或提问时，会取消拥有该交互的整个原生 Kernel Run，而不只是关闭卡片；同一 Kernel 上的其他 Run 不受影响。
- 本版本不承诺把暂停中的 Routine 审批跨完整进程重启恢复。热重载会保留可恢复审批；完整重启会把审批以 `producer_lost` 系统取消，并把对应 Run 诚实结算为 `FAILED + outcomeUnknown`，用户需要重新运行 Routine。后续若要支持跨重启继续，必须同时持久化并验证完整 continuation，而不能只保留审批卡片。
- Windows 安装包在 Authenticode 证书到位前仍未签名，首次下载或启动时 Microsoft Defender SmartScreen 可能继续警告。
