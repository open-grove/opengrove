# OpenGrove v0.6.6

[English](https://github.com/open-grove/opengrove/blob/v0.6.6/docs/releases/v0.6.6.md)

## 产品更新

- **Store App 升级更安全。** OpenGrove 现在会将可替换的 Store App 程序与持久的 Workspace 分开保存。程序迁移会在启用前完成校验，中断后可以恢复，不会阻塞启动，诊断信息也不会包含 Workspace 内容。
- **Agent 运行更可靠。** Codex、Claude Agent、Pi、ACP、Hermes 和 OpenClaw 会保留各自原生的工具、取消、交互与完成语义。可恢复的 Provider 错误不再会把整个 Run 误判为失败，取消某个 Run 也不会影响同一 Kernel 上的其他 Run。
- **审批结果更清楚。** 拒绝、取消和中断会保持明确区分。热重载可以保留能继续的审批；完整重启后，OpenGrove 会清楚提示需要重新运行，不会把未完成的操作伪装成已完成。

## 技术改进

- **发布信任边界更明确。** 公开 PR 需要 CODEOWNER 审批，桌面版最终化由受保护的 `desktop-release` environment 执行；首个公开 `v0.6.6` Release 使用校验和已固定的一次性引导路径，仍保留上一版更新门禁。
- **Run 生命周期只有一个权威来源。** `RunRecord.lifecycle.taskState` 现在使用 A2A TaskState 词汇。诊断 `error` 事件不再猜测终态，只有 `turn.finished.outcome` 会结算 Run。旧本地记录会在读取时迁移；API 调用方需要从 `run.status` 和 `/runs?status=` 迁移到 `run.lifecycle.taskState` 和 `/runs?taskState=`。
- **Kernel 能力证据更诚实。** Host、Kernel 版本、runtime mode 或 Provider 变化时，已认证能力会在排队复验期间保持可用；只有更新的明确失败或已删除的 contract mapping 才会隐藏能力。OpenClaw 已针对 `2026.8.2` 认证，包含 challenge 握手和 wire protocol v4。
- **兼容边界保持有限。** 待处理交互 API 现在可能返回 `canceled`；明确取消审批或提问会取消它所属的原生 Run。完整进程重启不会恢复未完成的 Routine 审批。Windows 安装包在 Authenticode 证书就绪前仍未签名，首次启动时 SmartScreen 仍可能警告。
