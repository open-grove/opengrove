# OpenGrove v0.7.0

[简体中文](https://github.com/open-grove/opengrove/blob/v0.7.0/docs/releases/v0.7.0.zh-CN.md)

## Product Updates

- Mobile and narrow-screen support: improved use in mobile browsers and narrow windows with drawer navigation, retained panel selection state, and better touch dragging. Desktop navigation also supports resizing, icon mode, and hiding, with improvements to unread indicators, spacing, and localized App names and icons.
- More reliable file editing: external changes are detected to prevent saves from silently overwriting newer content. Conflicts can be compared and resolved before saving, or the draft can be discarded. Unsaved drafts can be restored after navigation and page refresh.
- Clearer run and approval states: long tasks are less likely to be interrupted by a uniform time limit. Rejecting an operation, stopping a task, and losing its runtime are represented separately. Routine approvals that cannot resume after a full restart are explicitly marked as failed with an unknown outcome and must be run again; valid approvals can survive a hot reload.
- Better model and local tool integration: expanded Gemini and DeepSeek model discovery and model limit information, improved Pi protocol selection, and native file and command tools. Claude sign-in, Kimi installation discovery, and Windows Codex desktop installation discovery are improved to reduce cases where installed tools appear unavailable.
- More resilient account connections: temporary cloud failures preserve existing configuration and retry, while canceling one task does not interrupt credential recovery for other tasks. Expired hosted Web sessions return to sign-in instead of leaving the page unusable.
- Independent update controls: client updates can be checked while signed out, and checking no longer consumes session refresh credentials. Installed Apps have separate automatic update settings and checks, including checks while desktop windows are closed. Update notes support English and Simplified Chinese.
- Clearer storage management: categorized usage and cleanup controls coordinate with active operations and protect installers being downloaded. Legacy App directory migration and state lock recovery after abnormal exits are improved while preserving user data in App workspaces.
- Remote Agent collaboration: administrators can connect trusted Agent nodes, add remote Agents to Contacts, and start tasks through direct messages or mentions and quoted replies in group chats. Progress, reconnection, and retry are available. This release supports text messages; group requests include only the current message and explicitly quoted content. Stopping distinguishes ending the local wait from confirmed remote cancellation.

## Technical Improvements

- Unified Host operation contracts, the Client CLI, and OpenAPI so generated external clients share interface definitions with the server. The App release CLI uses common authentication for preparation, publishing, status, recovery, and applying a published version.
- File writes require explicit revision preconditions: missing expectedRevision returns 428, conflicts return 409, and creation is distinguished from updating an existing file. The editor uses this contract to coordinate local drafts, disk contents, and conflict resolution.
- Standardized Run lifecycle state under RunRecord.lifecycle.taskState, with migration and query compatibility for older records. Approvals and questions gain a canceled state and system reasons, preventing transport errors, lost runtimes, or pending cancellation from being recorded as normal completion.
- Updated the Claude Agent SDK, Pi, Electron, and related dependencies, with changes to native session, tool, cancellation, and model metadata integration. Existing Pi native session files are preserved, but their history is not imported to resume new sessions after this upgrade; work must continue in a new session.
- Integrated the Agent Router SDK with authorization isolated by the currently signed-in administrator and each run. Remote credentials remain in memory. This path does not grant remote Agents local Routine or delegated execution permissions.
- Strengthened App snapshot, activation, and recovery state management, coordinated storage maintenance with installer caching, and used operating system locks to identify running instances and reduce startup failures caused by stale locks.
- Added bilingual release notes and schema v3 gate receipts that bind candidate commits and artifact digests, with separate candidate build, GitHub Release finalization, registration, and promotion stages. The first public release uses fixed, real 0.6.5 installers to verify the upgrade path. Restricted test deployments also support team token admission.
