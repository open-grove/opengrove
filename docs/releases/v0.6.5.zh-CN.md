# OpenGrove v0.6.5

[English](https://github.com/open-grove/opengrove/blob/v0.6.5/docs/releases/v0.6.5.md)

OpenGrove v0.6.5 让 Store App 升级更安全，为符合条件的海外作者加入 Stripe Connect 提现开户流程，增强 App 命令与媒体链路的可靠性，稳定 Employee 的模型与思考等级默认值，并让 App 发布恢复动作和桌面发版准备状态更加明确。

## 主要变化

### 1. Store App 程序与持久 Workspace 分离

Store App 代码现在以并排的程序代际安装在持久 App Workspace 之外。安装、修复、回滚、正式版本切换以及发布后应用都只切换一个已挂载的程序指针，Workspace 路径与用户数据保持稳定。

升级迁移会在使用前验证每一条 Workspace 绑定。只有带有效清理标记的旧程序代际才会被移除；Windows 文件锁可以推迟清理，但不会阻止新版本激活。未知或格式异常的目录会被保留，而不是依靠猜测删除。错误导出包会加入结构化的 `store-app-layout.json`，记录新旧根目录、当前绑定、迁移残留与检查失败，但不会导出 Workspace 文件内容。

### 2. 符合条件的海外作者可以完成 Stripe 提现开户

由 WW 路由到 Stripe Connect 的作者可以从 OpenGrove 打开开户流程，通过对应的正式版或开发版桌面链接返回，同步账号状态，并查看提现进度和可恢复的补充要求；界面不会直接暴露上游错误。

国家或地区、提现服务商、结算币种、创作者签约状态与提现就绪状态仍由服务端决定。WW 只返回这组数据的一部分时，客户端会严格中止，也不会调用已退役的 Stripe consent 写入路径。

### 3. App 命令与 Routine 输出会明确失败

有意不产生输出的成功 App 命令会继续保持成功。结构化 JSON 与 Host 执行元数据相互隔离，Routine 引用支持业务输出的深层路径，字段缺失时会显示明确诊断，而不是投影成含义不明的值。

过大的结构化输出与无效 JSON 现在会返回稳定错误，不再尝试解析被截断的流。进程启动失败与进程 stderr 计数保持分离，受限和截断的诊断也会得到清晰标记。

### 4. 桌面媒体与 Room 同步可以干净恢复

MCP App 放弃媒体请求时，桌面代理现在会把取消传递给 Bridge 并关闭底层流。反复取消播放不再耗尽桌面连接，也不会遗留本地文件句柄，Windows 同样适用。

可恢复的 MCP App 面板失败可以原地重试。Room 刷新还会原子保存快照及其事件游标，避免重新连接跨过同步边界时漏掉或重复事件。

### 5. Employee 模型与思考等级默认值保持具体、稳定

新建的产品 Employee 与 App Employee 会获得能够通过既有 Provider 绑定解析的具体 Kernel/模型默认值。旧的空值或 `native` 模型会迁移一次；用户明确选择的 Kernel、Provider、有效模型和思考等级仍然具有最高优先级。

思考等级控件现在区分加载中、支持和不支持三种状态。能力加载期间仍会显示 Kernel 默认值；Provider 暂时不可用不会抹掉已知 Kernel 能力；Pi 会声明其支持的思考等级；保存回执也不再丢弃按 Kernel 保留的草稿。

### 6. App 发布恢复与桌面候选准备门禁更加严格

App 发布界面现在把 Release Control 返回的 `allowedActions` 作为重试与放弃选择的权威来源。失败阶段、稳定错误码与 workflow run 只作为诊断信息，不再由客户端据此重建服务端策略。

完整桌面候选会在签名构建前统一运行完整 release check，使用只读方式验证已配置部署服务的认证访问，重放当前已知良好的发版门禁，并对齐 Playwright 与运行时依赖版本。局部平台运行仍只用于诊断，不能提升为正式版。

### 7. 已退役的 Host 业务兼容层被移除

已退役的 Host 内置 Story Seed 工作管理与合同签署界面、旧的同源 web-app 挂载方式及其兼容策略被成组移除。当前 App 继续使用受支持的文件工作台、MCP App View、已声明命令与显式 WW session 注入。

内置运行时、协议、桌面、编辑器、图标、构建与测试依赖按审查后的组合升级。Claude Agent 保留按模型决定的默认工具集合，生成的 MCP App 示例则跟随当前 capability schema。

## 兼容性与迁移说明

- 本版本的 `clientReleaseNumber` 为 `10030`。
- 从 OpenGrove 0.6.4 升级不需要手工迁移本地数据。Store App 程序代际与 Workspace 绑定会自动迁移；未知文件和未经验证的清理目标会被保留。
- 海外 Stripe 提现能力要求先部署配套的 WW 结算响应和数据迁移。WW 必须完整返回 `country_code`、`payout_provider`、`cash_currency`，并通过 Stripe Connect 状态暴露由服务端决定的创作者签约结果。
- 仍依赖旧 `ui.kind=web-app` / `ui.kind=web`、已退役 Story Seed Host dashboard 或 Host 内置合同签署 prompt 的 App，必须在升级前迁移到受支持的 App surface 与已声明命令。
- npm 包发布与 npm 全局安装更新路径仍然停用。源码构建和桌面发布继续正常使用 npm。
- Windows 安装包在 Authenticode 证书到位前仍未签名，首次下载或启动时 Microsoft Defender SmartScreen 可能继续警告。
