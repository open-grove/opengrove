# OpenGrove v0.6.4

[Simplified Chinese](https://github.com/open-grove/opengrove/blob/v0.6.4/docs/releases/v0.6.4.zh-CN.md)

OpenGrove v0.6.4 adds recoverable formal App version management, simplifies Provider setup while separating Kernel account Login from model-service credentials, makes App Room ownership explicit and PM membership optional, gives supported ACP Kernels scoped Host Tools, adds new-account region collection, restores desktop MCP App media playback, and moves desktop deployment and promotion behind distinct trusted release gates.

## Highlights

### 1. Apps have recoverable drafts, releases, and exact version switching

Every visible App can keep one editable local draft while formal versions live in the independent Release Control service. Users can modify, preview, and save the draft locally, then select an exact formal version without changing the App workspace, Room history, or chat data. Real unsaved changes interrupt a version switch so the user can save, discard, or cancel first.

Admins can publish the App and its complete Employee configuration through a recoverable, idempotent transaction. Interrupted preparation, upload, or activation can resume safely; an unavailable Release Control service fails remote catalog and publishing actions explicitly while leaving local drafts open and editable.

### 2. Provider setup follows a curated catalog and keeps Login separate

OpenGrove now bundles a reviewed Models.dev snapshot for public Provider and model facts. Exact upstream model IDs remain intact, and separately named Fast, Free, Pro, HighSpeed, and regional routes stay distinct. The full model catalog is cached separately from the much smaller settings snapshot.

The main Provider list shows connected, enabled, or user-added services; inactive built-ins move to a searchable Add Provider dialog. OpenGrove no longer imports Provider configuration from other Kernels. Codex, Claude, and Kimi account Login is managed separately through native status, login, and logout commands, with interactive login opened in the system terminal and no copied or persisted login token.

### 3. App Rooms have explicit scope and an optional PM

App ownership is stored as explicit Room scope instead of being inferred from a Room ID or generated title. Punctuation, renamed Rooms, and ordinary Rooms that resemble an App can no longer change authorization or ownership.

The App PM is a default Employee rather than a mandatory system role. Apps may disable it, and users may remove it, demote it, or create a valid App group without one. Existing tombstones, membership, and administrator choices remain authoritative. Legacy App Room scope and collision-prone Employee identities migrate automatically while preserving messages, events, workflows, deleted-member references, and archived history.

### 4. ACP Kernels can use scoped OpenGrove Host Tools

Kimi and other ACP Kernels that support MCP Servers now receive an OpenGrove Host Tool bridge for both new and restored sessions. Each credential is bound to the concrete Session, Employee, Room, and allowed tool set, so an ordinary Room member can read the current Room without gaining cross-Room access or unauthorized delegation.

Tool execution continues through the existing permission, approval, and event-recording path. Session creation fails closed if the local tool bridge cannot start, and cleanup covers cancellation and restored sessions without changing the user's global Kernel configuration.

### 5. New-account registration records residence region explicitly

When WW reports that an email will create a new account, registration asks for a residence country or region from the complete ISO country list. Existing-account login is unchanged. The authenticated profile shows the registered account region as read-only.

The value is account service-availability metadata. It does not infer payment country, KYC country, or data-storage region, and OpenGrove adds no local account-data migration.

### 6. Desktop Apps regain local media playback and longer commands

MCP App media URLs now pass through the desktop protocol proxy to the authenticated local Bridge. Range requests and partial-content response headers are preserved, restoring cached audio and video playback without exposing arbitrary Bridge APIs or injecting user cookies into the App sandbox.

Declared App commands may now run for up to one hour instead of one minute, allowing legitimate long-running workflows while retaining argument, output-size, working-directory, and declared-command boundaries.

### 7. Desktop release deployment and activation are separate trusted stages

The release workflow builds and gates one immutable macOS Apple Silicon, macOS Intel, and Windows x64 candidate. Finalization creates the formal tag and GitHub Release from that candidate; deployment then verifies and uploads the same bytes before registering them with WW. Promotion is a separate protected action, so deployment never changes the active update pointer automatically and rollback or withdrawal remains explicit.

The source tree also adopts a privacy-safe public baseline and Apache-2.0 governance. User-facing `Claude Code` integration labels become `Claude Agent`; persisted Kernel IDs, sessions, models, and chat history do not change.

## Compatibility and Migration Notes

- `clientReleaseNumber` for this release is `10029`.
- No manual local-data migration is required from OpenGrove 0.6.3. App version, Room-scope, and Employee-identity migrations run automatically; ambiguous legacy App Rooms are archived with their history preserved rather than assigned an unsafe scope.
- The curated built-in Provider roster now contains 17 services. Retired presets such as Qianfan, SiliconFlow, ModelScope, StepFun, TheRouter, Novita, NewAPI, and N1N are no longer offered as built-ins; user-created custom Providers remain available.
- Provider configuration is no longer imported from Kernel configuration. Kernel account Login routes remain runtime projections and are never saved as custom Providers.
- Release Control imports only the current formal Store baseline. Already installed older App versions continue to run locally, but pre-cutover historical versions are not newly available for remote download.
- npm package publication and the npm-global `opengrove update` / `opengrove upgrade` path are disabled. Source builds and desktop releases continue to use npm normally.
- Windows installers remain unsigned until an Authenticode certificate is available, so Microsoft Defender SmartScreen can still warn on first download or launch.
