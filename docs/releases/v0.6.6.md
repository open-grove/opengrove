# OpenGrove v0.6.6

[Simplified Chinese](https://github.com/open-grove/opengrove/blob/v0.6.6/docs/releases/v0.6.6.zh-CN.md)

## Product Updates

- **Safer Store App upgrades.** OpenGrove now keeps replaceable Store App programs separate from your persistent Workspaces. Program migrations are checked before activation, can recover from an interruption, and never block startup or expose Workspace content in diagnostics.
- **More dependable Agent runs.** Codex, Claude Agent, Pi, ACP, Hermes, and OpenClaw retain their native tools, cancellation, interaction, and completion behavior. Recoverable provider errors no longer incorrectly mark the whole Run as failed, and canceling one Run does not disturb other Runs using the same Kernel.
- **Clearer approval behavior.** Rejected, canceled, and interrupted approvals remain distinct. A hot reload can preserve a resumable approval; after a full restart, OpenGrove clearly asks you to run it again instead of pretending that an unfinished action completed.

## Technical Improvements

- **Release trust is explicit.** Public pull requests require CODEOWNER review, desktop finalization runs behind the protected `desktop-release` environment, and the first public `v0.6.6` Release uses a checksum-pinned one-time bootstrap to preserve the normal previous-version updater gate.
- **Run lifecycle has one authority.** `RunRecord.lifecycle.taskState` now uses the A2A task-state vocabulary. Diagnostic `error` events no longer guess a terminal result; only `turn.finished.outcome` settles a Run. Older local records are migrated when read, while API consumers must move from `run.status` and `/runs?status=` to `run.lifecycle.taskState` and `/runs?taskState=`.
- **Kernel capability evidence stays honest.** Previously certified capabilities remain available while a changed Host, Kernel version, runtime mode, or Provider is queued for revalidation; only a newer explicit failure or removed contract mapping hides the capability. OpenClaw is certified against version `2026.8.2`, including its challenge handshake and wire protocol v4.
- **Compatibility remains bounded.** Pending-interaction APIs may now return `canceled`; an explicit approval or question cancellation cancels its owning native Run. Full-process restart does not resume an incomplete Routine approval. Windows installers remain unsigned until an Authenticode certificate is available, so SmartScreen may still warn on first launch.
