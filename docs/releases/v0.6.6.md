# OpenGrove v0.6.6

[Simplified Chinese](https://github.com/open-grove/opengrove/blob/v0.6.6/docs/releases/v0.6.6.zh-CN.md)

OpenGrove v0.6.6 separates replaceable Store App programs from user-owned Workspaces and establishes the public repository's reviewed contribution and first-release path.

## Highlights

### 1. Store App program migration is copy-validated and recoverable

Replaceable Store App programs migrate independently from persistent user Workspaces. The migration validates copied program generations before activation, keeps legacy data available for recovery, rolls back incomplete changes, and never blocks OpenGrove startup. Diagnostic exports record the layout and migration state without including Workspace contents.

### 2. Public pull requests and desktop finalization use explicit trust boundaries

Public pull requests require review by a repository administrator represented in CODEOWNERS. Desktop finalization now uses the protected `desktop-release` environment, while one release operator may still approve and complete the workflow without a second operator.

### 3. The first public release preserves the normal N-1 updater gate

Because the new public repository has no earlier GitHub Release, the `v0.6.6` candidate can use one checksum-pinned bootstrap to verify updates from the existing `v0.6.5` production installers. The path is rejected for every other version and after the first public GitHub Release exists; later releases use the normal previous-GitHub-Release path.

## Compatibility and Migration Notes

- `clientReleaseNumber` for this release is `10031`.
- No manual Workspace migration is required. The Store App layout migration is startup-safe and retains legacy sources until validated cleanup is allowed.
- The first-public-release workflow option is release infrastructure only; it does not change installed-client behavior or product authentication.
- Windows installers remain unsigned until an Authenticode certificate is available, so Microsoft Defender SmartScreen may still warn on first download or launch.

## Verification

- Public-release bootstrap manifest, download identity, and workflow contract checks
- Full three-platform candidate, installed-artifact smoke, updater metadata, and v0.6.5-to-v0.6.6 update gates
